# Универсальный каркас: сайт + воронка + умный ассистент

Документ — схема сборки типового клиентского продукта из готовых частей.
Цель: под нового заказчика собирать базовый сайт за дни, а не недели, меняя
контент, палитру и персоналию ассистента, а не архитектуру.

---

## 1. Что мы делаем

Мы делаем **не сайт «под ключ с нуля», а сборку из универсального каркаса**.
Каркас рассчитан на малый бизнес, который **продаёт товар или услугу**:
аптека, автосервис, сантехник, страховой агент/оценщик — все они однотипны
в том смысле, что им нужно:

1. **Сказать, что продают** — витрина: услуги/товары, цены, контакты, доверие.
2. **Принимать обращения** — форма заявки и чат с посетителем.
3. **Вести клиента** — воронка: заявка не теряется, движется по этапам.

Отсюда **базовая комплектация — три вещи**:

| # | Вещь | Что это | Референс (уже сделан) |
|---|------|---------|------------------------|
| а | Сайт | Витрина: шапка, hero, услуги, статьи, точки, форма заявки | `public/experiments/ocenka-site-v2/` |
| б | Канбан-воронка | Доска для владельца/менеджера: карточки клиентов по этапам | `public/experiments/chat-engine/` (дашборд) |
| в | Умный ассистент | Виджет на сайте: диалог → LLM-черновик ответа → менеджер утверждает | `public/experiments/chat-engine/widget.html` + `server/services/chat-engine/` |

Пилот на проекте «Страхование и оценка» (Курск) отработал все три части —
он и есть носитель шаблонов для следующих заказчиков.

## 2. Технологический стек

- **Сервер**: обычный Linux VDS; nginx (статика + reverse proxy, конфиг — `docs/deploy-linux-vds.md`), процесс под systemd или pm2.
- **Бэкенд**: Node.js 20+ / Express, тонкие роуты; вся логика — в сервисных классах (`server/services/<id>/`).
- **База**: PostgreSQL 16; docker или нативная установка — переключается переменной `DB_MODE` (`server/config.js`); схема только через нумерованные миграции `db/migrations/NNN_<id>.sql`.
- **Фронт**: vanilla JS/CSS, без фреймворков и сборки (регламент — `docs/experiments.md`); один веб-шрифт (Google Fonts) с системным фолбэком.
- **LLM**: только server-side клиент, ключи исключительно в `.env` на сервере; при сбое — честный отказ (`{ok:false}`), никаких выдуманных ответов.
- **Таймеры**: рекурсивный `setTimeout` (никогда `setInterval`).
- **Архитектурный канон**: `docs/oop-principles.md` — точка сборки (П3), дверь территории — все операции домена через один класс (П28/П27), тонкий транспорт (П9), один глагол (П12).
- **Структура одного проекта** (по регламенту экспериментов): `public/experiments/<id>/` (index.html, css, js), `server/routes/<id>.js`, `server/services/<id>/`, миграция, плитка в `public/experiments/registry.json`, монтирование `/api/<id>` в `main.js`.

## 3. Схема витрины (публичная часть сайта)

Блоки сверху вниз; образец реализации — `ocenka-site-v2`:

1. **Шапка**: логотип-марка + название; навигация (Услуги · Статьи · Контакты · Заявка); телефон крупно; CTA-кнопка («Заказать звонок»); на мобильном — бургер.
2. **Hero**: pill-метка («Город · работаем с … года»), H1 с одной выделенной фразой (градиентный текст), подзаголовок «что + для кого + выгода», две кнопки (основной CTA + призрачный), карточка доверия справа: рейтинг, 3–4 цифры (лет на рынке, офисов, клиентов, «0₽ консультация»).
3. **Услуги** — карусель **или** гармошка:
   - **Карусель** (3D coverflow, без WebGL): когда услуг 5–10 и их выгодно показывать «витриной». Правила шаблона — в `docs/ui-carousel-modal.md` (проект my-service-back), рабочая реализация — `ocenka-site-v2`: центральная карточка крупнее, автопрокрутка рекурсивным `setTimeout` с паузами (наведение/модалка/вне экрана), колесо мыши крутит карусель **только в узкой полосе-отблеске** по центру, иначе прокручивается страница; клик по карточке открывает модалку (720px / 80vh) с описанием и характеристиками; листание в модалке синхронно с лентой; `prefers-reduced-motion` — обычная лента.
   - **Гармошка**: когда услуг много (>10), они длинные или иерархичные (прайс, категории) — каждый пункт: заголовок + разворот с деталями и CTA.
4. **Статьи/вопросы**: 3–4 карточки с тегом; снимают типовые боли и добавляют доверие + SEO.
5. **Точки/контакты**: адреса, режимы работы; карта — по желанию.
6. **Блок заявки**: имя + телефон + кнопка (минимум полей!), рядом — кнопка чата.
7. **Футер**: реквизиты, соцсети, телефон; для демо — дисклеймер «макет для переговоров».
8. **Плавающий виджет-чат** (§5) — пилюля в правом нижнем углу.

## 4. Кабинет (админская часть)

Одно приложение — **два лица**: витрина публична, кабинет — за авторизацией.

- **Авторизация**: логин+пароль (bcrypt), сессионная cookie; таблица `users`; защита `/admin` и `/api/<id>/admin/*`. В базовой версии — без ролей (владелец + менеджер).
- **Вкладки кабинета**: **Воронка** (канбан), **Диалоги** (чат с клиентами), **Настройки** (персона ассистента, услуги).
- **Канбан-воронка**: этапы настраиваются под отрасль заказчика (образец: Новая → В работе → Предложение → Согласование → Успех/Отказ); колонки с цветными рамками и счётчиками, карточки «имя + время + суть», статусы двигаются вручную и автоматически (события диалога). Референс: `chat-engine/index.html` + `dashboard.js` + `server/services/chat-engine/Funnel.js`.
- **Адаптивность доски**: ≤640px — 3×2; планшет — 3+3; ~1200px — 6 в линию; широкие экраны — дорожки-этапы слева + чат справа (media-запросы, референс `chat-engine.css`).
- **Стиль кабинета** — «приборная панель»: плотный, материальные фаски и утопленные колодцы (тема chat-engine) — рабочая среда должна отличаться от витрины.

## 5. Умный ассистент (виджет-диалог)

Схема потока (реализована в chat-engine, переносится как есть):

```
виджет на витрине → сообщение посетителя → БД + колонка «Новая»
  → LLM предлагает черновик (персона + карточка + история)
  → менеджер утверждает / правит / отклоняет
  → ответ уходит в виджет → событие двигает карточку воронки
```

Компоненты (образцы в `server/services/chat-engine/`):

- `DialogueRepository` — весь SQL, транзакции, dedup по `external_id`.
- `ReplySuggester` — промпт: дата + персона + карточка + последние 30 сообщений; честный `{ok:false}` при сбое LLM.
- `ChatDesk` — дверь территории: все операции домена только через этот класс (П28).
- `Funnel` — этапы и их цвета.
- Миграция-образец: `db/migrations/012_chat_engine.sql` — диалоги (UNIQUE channel+visitor), сообщения (роли visitor/manager/draft, состояния open/sent/approved/edited/rejected/superseded), журнал этапов, KV-настройки (персона).
- Виджет: `widget.html` + `widget.js` — опрос рекурсивным `setTimeout` (2.5 с), кнопка «вернуться к дашборду» — только в демо-режиме.
- **Каналы** уже абстрагированы (`channel` в диалогах): web-виджет сейчас, vk/telegram — рост-точка без смены движка.

## 6. База данных (минимум каркаса)

`users` · `dialogues` · `messages` · `stage_log` · `settings` (KV).
Услуги, точки и статьи в базовой версии лежат статикой во фронтенде
(быстро править и деплоить); переезд в БД — осознанная рост-точка, когда
заказчик просит админку контента.

## 7. Дизайн

**Набор из трёх тем витрины**: «А Стекло» описан ниже; «Б Пространство»
(псевдо-3D на CSS + Zdog) и «В Милый брутализм» — в [ui-designs.md](ui-designs.md).

**Витрина — современная лёгкая тема (тема А):**

- **Светлая база** — дефолт для доверительных отраслей (шпаргалка, разрез 3: light выигрывает на читаемости, тёмная — опция/«вечерняя» тема по желанию заказчика, образец — `ocenka-site-v2`).
- **Bento** — сетка карточек разного размера для услуг/цифр/статей.
- **«Жидкое стекло»** — полупрозрачные поверхности (`rgba(255,255,255,.05–.09)`), `backdrop-filter: blur`, 1px светлые рамки, крупные радиусы (18–26px).
- **Мягкие градиенты** — радиальные «блобы» фона (тёплый + холодный), градиентный текст одной ключевой фразы hero, градиентная заливка CTA; никакой резкой неоновой пестроты.
- **Кабинет** — контрастная по духу «приборная панель»: плотнее, материальнее (фаски, колодцы) — см. §4.

**Палитра — только через [docs/ui-color-cheatsheet.md](ui-color-cheatsheet.md):**
разрез 2 даёт доменный скелет (финтех/страхование — синий+бирюза на светлой базе, еда — красный+жёлтый, spa — пастель…), разрез 1 — психологию акцентов, разрез 3 — контекст задачи и light/dark, разрез 4 — инженерию (роли по Radix, WCAG 4.5:1/3:1, OKLCH). Там же — алгоритм подбора за 10 шагов.

**Правила ролей цвета** (выведены на ocenka-site-v2, коммит `f8c37af`):
один тёплый акцент **только у CTA**; доверительная роль (синий/бирюза) — для ссылок, тегов, иконок, фокуса; success/warning/error — отдельная семантика; серые тексты ≥ 4.5:1; состояния кодируются не только цветом.

## 8. Чек-лист сборки под нового заказчика

1. **Бриф**: отрасль → доменный скелет палитры (шпаргалка, разрез 2); собрать услуги (5–9), точки, статьи, цифры доверия, фото/эмодзи услуг.
2. **Новый проект-эксперимент** по `docs/experiments.md`: плитка в `registry.json`, роут, сервис, миграция, запись в `main.js`.
3. **Скопировать референсы**: витрину из `ocenka-site-v2`, кабинет и ассистент из `chat-engine`.
4. **Палитра**: пройти алгоритм 10 шагов из шпаргалки; заменить токены `:root` (фон/текст/границы/акцент CTA/доверие/семантика) — компоненты уже завязаны на токены.
5. **Каркас витрины**: шапка → hero с цифрами → услуги (карусель или гармошка по §3) → статьи → точки → заявка → футер → кнопка чата.
6. **Воронка**: этапы под процесс заказчика; персона ассистента под отрасль (тон, специализация, что советовать).
7. **`.env` и БД**: `DATABASE_URL`/`DB_MODE`, LLM-ключи; прогнать миграцию.
8. **Деплой** по `docs/deploy-linux-vds.md`: nginx + certbot + systemd/pm2; проверка на VDS.
9. **Проверки перед демо**: контраст (шпаргалка, разрез 4), мобильный 390px (карусель, модалка, доска), колесо мыши не перехватывается вне полосы, честный отказ LLM без ключа, авторизация кабинета.
10. **Демо заказчику**: ссылка на витрину + кабинет; правки; договорённость о сопровождении.

## 9. Рост-точки каркаса

- **Каналы**: vk / telegram мессенджеры в тот же движок диалогов (`channel`), виджет как одно из «лиц».
- **Контент из БД**: услуги и статьи в админке (заказчик правит сам).
- **Онлайн-запись / каталог товаров** (аптека, автосервис) — расширение витрины.
- **Генератор тем «под отрасль»**: скелет ролей Radix + OKLCH, вход — домен заказчика, выход — готовые токены (идея из шпаргалки).
- **Мультиаренда**: один инстанс — несколько заказчиков (`tenant_id` в диалогах/воронке).
