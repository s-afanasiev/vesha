# 4.2. Стандарт исследования

Правила, по которым пишется любой документ исследования [«Фундаментальные драйверы силы национальной экономики»](../economic-strength-roadmap.md): типы и коды, шаблон, данные и источники, разметка утверждений и уверенность, рецензирование. Направление 4.2 лёгкое и потому оформлено одним документом (план, 0.8): подтемы 4.2-A…E — разделы 3.A…3.E.

## 0. Резюме

- **Вопрос:** как сделать так, чтобы сотня документов от разных авторов и сессий складывалась в одно проверяемое исследование, а не в сотню мнений.
- **Ответ — пять правил.** Один код из реестра — один файл с YAML-шапкой и обязательными разделами по типу (3.A, 3.B). У каждой цифры есть паспорт ряда или ссылка на источник, расчёт воспроизводится одной командой (3.C). Каждое числовое утверждение и каждый вывод размечены: факт, оценка, гипотеза или мнение, — а у вывода указана уверенность (3.D). Документ получает статус «принят» только после рецензии владельца исследования, а чувствительные темы — ещё и после «адвоката дьявола» (3.E). Нет данных — так и пишем, с причиной (3.C.5).
- **Что делать:** писать документы волны 0 по этому стандарту; после трёх документов — ретроспектива и версия 1.0 стандарта.
- **Уверенность:** средняя — правила взяты из проверенных практик (раздел 2), но на документах этого исследования ещё не опробованы.

## 2. Основания

- **Метаданные статистики** — стандарт SDMX и практика статистических служб: у каждого ряда есть паспорт, у паспорта — обязательные поля.
- **Шкалы уверенности** — три источника с общей идеей «отделять качество доказательств от силы вывода»: аналитические стандарты разведывательного сообщества США (ICD 203) со словарём вероятностей, руководство МГЭИК по согласованному описанию неопределённости (уверенность и вероятность раздельно), система GRADE доказательной медицины (уровни качества доказательств).
- **Рецензирование** — практика научных журналов и аналитических центров плюс приём «красной команды»: отдельный рецензент, чья задача — найти сильнейшие контраргументы.
- **Принципы репозитория** — пятно должно быть видно, а не спрятано: «не проверяли», «данных нет» и «данные закрыты» — разные статусы (так же устроены разборы ниш в [automation-leads-architecture.md](../../automation-leads-architecture.md)).

## 3. Правила

### 3.A. Типы, коды, жизненный цикл

#### 3.A.1. Типы документов

| Тип | Назначение | Объём | Обязательно внутри | Рецензия |
|---|---|---|---|---|
| **W** — whitepaper | синтез направления или блока, позиция и рекомендации | 30–60 стр. | вердикты по всем гипотезам, которых касается; ссылки на все входящие документы | владелец + адвокат дьявола |
| **A** — аналитическая записка | ответ на вопросы одной подтемы | 10–25 стр. | ответ на каждый вопрос плана или причина, почему ответа нет | владелец; адвокат дьявола — по списку 3.E.2 |
| **D** — датасет | таблицы, паспорта рядов и записка к ним | таблицы + 5–10 стр. | паспорт каждого ряда, скрипт сборки, описание разрывов | владелец; выборочная сверка 10 % значений с источником |
| **K** — кейс-досье | сравнительный разбор кейсов | 15–30 стр. | правило отбора кейсов, включая провалы; одинаковые оси сравнения для всех кейсов | владелец; адвокат дьявола — по списку |
| **M** — методика | воспроизводимый способ расчёта или оценки | 5–15 стр. + код | формулы, допущения, пример расчёта, проба на реальном документе | владелец + проба применения |
| **S** — скоринговая карточка | оценка одного продукта по формуле 4.1 | 1–2 стр. | баллы с обоснованием и интервалом, G-фильтры, квадрант | владелец; для своих продуктов — адвокат дьявола (3.E.4) |

#### 3.A.2. Коды, имена, версии, ссылки

- **Код документа** — из реестра плана: `1.0-A`, `3.2-A4`, `1.1-Σ`, `1-Σ`, `Σ`; для лёгкого направления, оформленного одним файлом, — код направления (`4.2`). Скоринговые карточки — `4.1-E/01`, `4.1-E/02`, ….
- **Имя файла** — `<код>-<slug>.md`, slug — английский kebab-case; «Σ» пишется как `sum`: `1.1-sum-institutions.md`, `sum-final-report.md`. Карточки — в папке `4-method/4.1-E-cards/` с именами `01-<slug>.md`.
- **Папка** — по блоку: `1-foundations/`, `2-tactics/`, `3-software/`, `4-method/`; итоговый доклад — в корне `docs/economic-strength/`.
- **Версия** — `0.x` для черновика; `1.0` при первом принятии; `1.x` — уточнения, которые не меняют выводов; `2.0`, `3.0`, … — изменился хотя бы один вывод раздела 6 или вердикт по гипотезе. Каждое изменение версии — строка в журнале версий.
- **Ссылки** — относительные markdown-ссылки на файл и раздел. Короткая форма ссылки на вопрос плана — `1.1-A/в2` (подтема 1.1-A, вопрос 2); на ряд данных — `1.0-B/<id ряда>`.

#### 3.A.3. Жизненный цикл

| Статус | Что означает | Условие входа | Кто переводит |
|---|---|---|---|
| план | строка в реестре, файла нет | — | — |
| черновик | файл создан, идёт работа | начата работа над документом | автор |
| ревью | автор считает ответы полными | самопроверка по чек-листу 3.E.5 пройдена, рецензенты названы в шапке | автор |
| принят | документ можно цитировать как результат | все рецензии закрыты (3.E.3) | владелец исследования |
| на пересмотре | вывод может быть неверен | вышли новые данные, изменился вывод документа из `depends_on` или рецензент нашёл ошибку после принятия | любой участник, с записью причины в журнал |
| устарел | документ заменён | есть замена, она указана в поле `replaced_by` | владелец исследования |

Статус живёт в шапке файла; реестр плана (Приложение А) берёт его оттуда скриптом `scripts/economic-strength-registry.mjs`.

#### 3.A.4. Обновление

- **D и S** — при выходе новых данных источника, но не реже раза в год. Обновление данных без изменения выводов — версия `1.x`.
- **A и K** — при изменении выводов документов из `depends_on` и по сигналу рецензента.
- **W** — после принятия всех входящих документов и при смене мажорной версии любого из них.
- **M** — при изменении метода; все документы, которые методикой пользуются, получают запись в журнал «метод обновлён, вывод не меняется / меняется» и при необходимости переходят в «на пересмотре».
- **Каскад.** Мажорная версия документа обязывает проверить все документы из его `feeds`. Проверка — строка в их журналах, а не автоматический перевод в «на пересмотре»: большинство изменений не меняет зависимых выводов.

Номера разделов сохраняются, даже если раздел пропущен по типу: раздел 6 всегда «Выводы». Пропущенный раздел просто не пишется.

#### 3.B.3. Резюме

Не больше 300 слов, пять пунктов в фиксированном порядке:

1. **Вопрос** — одной фразой.
2. **Ответ** — двумя-тремя фразами, без оговорок, которые есть в разделе 8.
3. **Три числа** — главные цифры документа с разметкой и источником.
4. **Что делать** — для политики, для продукта или для следующих документов.
5. **Уверенность** — уровень по 3.D.2 и главное ограничение.

#### 3.B.4. Связь вопросов плана с ответами

- В разделе 1 вопросы плана приводятся дословно, с номерами.
- В разделе 3 у каждого вопроса свой подраздел: «3.1. Вопрос 1: <текст дословно>», «3.2. Вопрос 2: …». Ответ начинается с короткого вывода, потом доказательства.
- Если ответа нет — подраздел остаётся и говорит: «Не удалось ответить: <причина>. Что нужно: <данные, доступ, метод>».
- Если работа показала, что вопрос поставлен неверно, — подраздел объясняет почему и предлагает новую формулировку; план правится отдельной записью в его журнале версий.
- **Исключение для методик (M).** Раздел 3 методики — правила, а ответы на вопросы плана часто даёт проба применения в разделе 4. Поэтому методика вместо подразделов-вопросов в разделе 3 ведёт таблицу соответствия в разделе 1: «вопрос плана → раздел с ответом»; подраздел с ответом начинается с короткого вывода и уверенности, как и в записке.

### 3.C. Данные и источники

#### 3.C.1. Паспорт ряда

Паспорт — запись в файле `data/<код>/passports.md` (или в разделе 2 документа, если рядов меньше пяти).

| Поле | Что писать |
|---|---|
| `id` | короткий латинский идентификатор, уникальный внутри документа: `unemp_rate` |
| название | по-русски, как в тексте |
| единица | %, млрд руб. в текущих ценах, тыс. чел., индекс 2015 = 100 … |
| частота и охват | год, квартал, месяц; страны или регионы; годы с … по … |
| источник | организация, таблица или форма, раздел |
| адрес | URL таблицы или API-запрос; для ручного ввода — откуда выписано |
| дата загрузки | ГГГГ-ММ-ДД |
| уровень источника | 1–6 по 3.C.2 |
| метод | как получено: напрямую, пересчёт (формула), склейка рядов, зеркальная статистика |
| ограничения и разрывы | смена методики, пересмотры, закрытые годы, ручной ввод из скана |
| версия | номер версии данных, если источник их ведёт |
| условия использования | лицензия или правила источника |

#### 3.C.2. Уровни источников и расхождения

| Уровень | Источники | Примеры |
|---|---|---|
| 1 | официальная статистика и регуляторы | Росстат, ЦБ РФ, Минфин, ФНС; национальные статслужбы стран панели |
| 2 | международные организации | Всемирный банк, МВФ, OECD, ООН, WIPO, UNIDO |
| 3 | научные центры и отраслевые ассоциации | ИСИЭЗ ВШЭ, ИНП РАН, IFR, НАУРР, «Руссофт» |
| 4 | отчётность и раскрытия компаний | годовые отчёты, ГИР БО, раскрытия эмитентов |
| 5 | консалтинг, отраслевые медиа, СМИ | обзоры рынков, TAdviser |
| 6 | экспертные оценки и интервью | интервью, опросы экспертов |

Альтернативные данные (вакансии, закупки, репозитории кода, отзывы) получают уровень своего первоисточника и пометку «альтернативные» в паспорте.

**Расхождения.** Если два источника расходятся больше чем на 10 %, документ показывает оба значения и объясняет причину (методика, охват, дата пересмотра). Выбор по умолчанию: для межстрановых сравнений — гармонизированный ряд международной организации; для динамики внутри страны и разбивки по отраслям и регионам — национальная статистика. Источник уровня 5–6 не может быть единственным основанием цифры в резюме.

#### 3.C.3. Воспроизводимость

- Расчёт каждого документа лежит в `docs/economic-strength/data/<код>/`: скрипт, итоговые таблицы в CSV (до 1 МБ на файл), паспорта и `README.md` с одной командой запуска.
- Сырые выгрузки — в `data/economic-strength/<код>/raw/` в корне репозитория (вне git); в имени файла — дата загрузки. Воспроизвести документ можно по скрипту и адресам из паспортов, не имея сырых файлов.
- Цифра в тексте ссылается на ряд или на источник: `[Ф: 1.0-B/unemp_rate, 2025]` или `[Ф: Росстат, ОРС, 2025]`.
- Ручные вычисления в тексте документа запрещены, кроме тривиальных (разность двух приведённых чисел); всё остальное — в скрипте.

#### 3.C.4. Автоматический сбор

- В автоматический конвейер попадают только машиночитаемые источники: API, CSV и XLSX, HTML-таблицы, PDF с текстовым слоем.
- Сканы в конвейер не попадают и через OCR не прогоняются. Если цифра нужна только из скана, человек выписывает её вручную, паспорт помечает «ручной ввод из скана», значение сверяет второй человек или вторая сессия.
- Сбор бережливый: пауза между запросами, остановка при отказе доступа, без обхода защиты — по тем же правилам, что у сборщиков VESHA ([collectors-architecture.md](../../collectors-architecture.md)).
- Персональные данные не собираются; интервью обезличиваются до роли («технический директор завода, 200 чел.»).

#### 3.C.5. Белые пятна

Отсутствие данных — результат, а не повод промолчать. Статусы различаются:

| Формулировка | Когда |
|---|---|
| «не искали» | вопрос вне объёма этой версии документа |
| «искали, не нашли» | перечислено, где искали |
| «данные закрыты» | источник был, перестал публиковаться; указано, с какого времени |
| «данных нет в природе» | показатель никто не измеряет; указано, как его можно измерить |

### 3.D. Разметка утверждений и уверенность

#### 3.D.1. Разметка

| Метка | Что означает | Обязательная ссылка |
|---|---|---|
| **[Ф]** факт | наблюдаемое значение из источника | ряд или источник |
| **[О]** оценка | результат расчёта или модели автора | метод (раздел 2 или скрипт) |
| **[Г]** гипотеза | утверждение, которое документ не проверял | что его проверит |
| **[Э]** мнение эксперта | суждение интервьюируемого или панели | роль эксперта, дата |

Размечаются все числовые утверждения и все выводы в разделах 0, 3 и 6. Определения, общеизвестные факты и пересказ плана не размечаются. Метка ставится в конце утверждения, перед точкой: «… выросла вдвое [О: скрипт 2.2-B]».

#### 3.D.2. Уверенность вывода

| Уровень | Критерии |
|---|---|
| **высокая** | два и более независимых источника уровня 1–3 сходятся; метод устойчив к разумным изменениям допущений; альтернативные объяснения рассмотрены и отвергнуты |
| **средняя** | один надёжный источник или несколько слабых; метод с существенными допущениями; часть альтернатив не исключена |
| **низкая** | косвенные данные, экспертные оценки, малые выборки; вывод чувствителен к допущениям |

Уверенность ставится каждому выводу раздела 6 и документу в целом (поле `confidence` — по самому важному выводу, а не по среднему).

#### 3.D.3. Неопределённость чисел

- Оценка [О] без интервала допускается, только если её ошибка меньше точности округления. В остальных случаях — интервал («12–18 %») или сценарии («базовый / низкий / высокий»).
- Для прогнозов и моделей — анализ чувствительности к главным допущениям: какое допущение сильнее всего двигает результат.
- Вероятность событий описывается фиксированным словарём, чтобы одно слово значило одно и то же во всех документах:

| Слово | Вероятность |
|---|---|
| почти наверняка | больше 90 % |
| вероятно | 60–90 % |
| примерно поровну | 40–60 % |
| маловероятно | 10–40 % |
| почти исключено | меньше 10 % |

### 3.E. Рецензирование

#### 3.E.1. Роли

| Роль | Кто | Задача |
|---|---|---|
| автор | агентская сессия или человек | пишет документ, проходит самопроверку по чек-листу |
| владелец исследования | Сергей Афанасьев | читает каждый документ; без его рецензии статуса «принят» нет |
| адвокат дьявола | отдельная агентская сессия с чистым контекстом | получает только документ и план; ищет сильнейшие контраргументы, ошибки в данных, подгонку выводов, пропущенные кейсы провалов |
| предметный рецензент | внешний эксперт, когда есть | проверяет отраслевые факты и интерпретации |

Адвокат дьявола не видит переписки, в которой документ писался: так он не наследует допущений автора.

#### 3.E.2. Сколько рецензий нужно

- Всем документам — рецензия владельца.
- Адвокат дьявола обязателен для: всех W и всех синтезов Σ; направлений 1.1 (институты) и 3.1 (критика поверхностного IT); документов 3.3-D и 4.1-C; всех скоринговых карточек собственных продуктов (3.E.4).
- Методики M дополнительно проходят пробу: применение к одному реальному документу, результат пробы — запись в рецензиях.
- Датасеты D дополнительно проходят сверку: 10 % значений, выбранных случайно, сравниваются с источником.

#### 3.E.3. Как записывается рецензия

Каждое замечание — строка таблицы «Рецензии» в самом документе: номер, рецензент, замечание, ответ автора, статус. Статусы замечания: «принято» (документ исправлен), «отклонено» (с причиной), «вынесено в ограничения» (раздел 8). Замечание считается закрытым, когда у него есть любой из этих статусов и рецензент с ним согласился или владелец исследования принял решение.

#### 3.E.4. Конфликт интересов

- Автор раскрывает в поле `conflicts` любую связь с продуктом, вендором, заказчиком или ведомством, о которых пишет документ.
- **Свои продукты — всегда конфликт.** Скоринг продуктов VESHA и смежных идей (план, Приложение Б) оценивает то, что мы сами делаем. Поэтому для таких карточек: адвокат дьявола обязателен, балл M без полевого замера у клиента не выше 5, а в выводах явно сказано, что оценка своя.
- Конфликт не запрещает писать документ, но меняет требования к доказательствам: выводы в пользу стороны, с которой есть связь, требуют уверенности не ниже средней.

#### 3.E.5. Чек-лист перед статусом «принят»

- [ ] На каждый ключевой вопрос плана есть подраздел с ответом или с причиной, почему ответа нет (3.B.4).
- [ ] У каждой цифры есть паспорт ряда или ссылка на источник (3.C.1).
- [ ] Расчёты воспроизводятся одной командой (3.C.3).
- [ ] Утверждения размечены, у каждого вывода указана уверенность (3.D).
- [ ] Белые пятна названы своими статусами (3.C.5).
- [ ] Гипотезы, которых касается документ, получили вердикт.
- [ ] Альтернативные объяснения рассмотрены письменно.
- [ ] Рецензии закрыты, обязательный адвокат дьявола пройден (3.E.2, 3.E.3).

## 4. Пример применения

Фрагмент записки по шаблону. Значения — заглушки N, чтобы пример не выдавал выдуманные цифры за данные.

```markdown
### 3.1. Вопрос 1: Какие профессии имеют наибольшее соотношение вакансий к соискателям?

Острее всего дефицит наладчиков станков с ЧПУ и сварщиков: на одного соискателя
приходится N вакансий против N в среднем по рынку [Ф: 2.1-A/hh_ratio, 2026-09].
За два года разрыв вырос в N раз [О: скрипт 2.1-A, разность рядов]. Дефицит,
вероятно, сохранится до 2028 г. [О: модель 1.2-F, базовый сценарий; интервал N–N].

Уверенность: средняя — один источник уровня 3 (вакансии), официальной статистики
по этим профессиям с месячной частотой нет («данных нет в природе»; измерить можно
обследованием предприятий, см. 8).
```

## 5. Рассмотренные альтернативы

| Альтернатива | Решение | Почему |
|---|---|---|
| Отдельный файл на каждый пункт раздела 0 плана | отклонено | раздел 0 — договорённости плана, у его пунктов есть исследовательские двойники (план, 0.8) |
| Заготовки сразу на все документы реестра | отклонено | пустые файлы создают видимость прогресса; статус «план» показывает пятно честнее |
| Числовая уверенность выводов (0–100 %) | отклонено | ложная точность; числа оставлены только для словаря вероятностей событий |
| Данные в таблицах облачного сервиса или в БД | отложено | нужны след в git и воспроизводимость; вернуться, если таблицы документа перерастут 1 МБ |
| Рецензия только владельцем, без адвоката дьявола | отклонено для чувствительных тем | в темах 1.1, 3.1 и в оценке своих продуктов высок риск подгонки выводов |
