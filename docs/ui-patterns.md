# Каталог UI-паттернов каркаса

Документ — словарь готовых «кусков UI» для наполнения витрины (§3
[universal-framework.md](universal-framework.md)) и кабинета (§4). Каркас
говорит, из каких блоков состоит сайт; здесь — чем их заполнять:
заимствованные паттерны, несколько авторских элементов и инженерный слой,
который платформа даёт без фреймворков. Материя поверх каркаса (темы
А «Стекло», Б «Пространство», В «Милый брутализм») — в
[ui-designs.md](ui-designs.md), цвет — только через
[ui-color-cheatsheet.md](ui-color-cheatsheet.md).

Общие правила всех паттернов (из каркаса, §2): vanilla JS/CSS без
фреймворков и сборки; таймеры — рекурсивный `setTimeout`;
`prefers-reduced-motion` обязательна; состояния кодируются не только цветом;
колесо мыши не перехватывается широкими зонами (правило карусели §3.3);
никаких выдуманных данных — паттерн показывает только то, что реально есть
(в демо — пометка «макет»).

## 0. Легенда

Зоны — по вопросу посетителя или работника:

| Зона | Вопрос | Паттерны |
|---|---|---|
| Конверсия | «Как оставить заявку?» | квиз→ассистент, калькулятор, sticky CTA, bottom sheet |
| Доверие | «Можно ли верить?» | до/после, отзывы, документы, таймлайн, пилюля режима, count-up, marquee |
| Витрина | «Что вы продаёте?» | сегмент-контрол, spotlight (+ карусель/гармошка — §3.3 каркаса) |
| Кабинет | «Как работать с потоком?» | WIP-шкала, sparklines, drag&drop, toast, empty states |

Цена: **CSS-only** — JS только на хвостах (десяток строк); **JS-lite** — до
~80 строк, без библиотек; **связка** — касается chat-engine или воронки.

## 1. Конверсия: заявка → воронка

Самая ценная зона: эти паттерны кормят воронку, а не украшают страницу.
RU-практика (квизы у Т-Банка, сценарии Tilda, калькуляторы) показывает, что
вовлекающие лид-формы бьют обычную «имя+телефон»; цифру «конверсия выше на
60–80%» считаем маркетинговой, направление верное. Оценка — как раз ниша
«цену называем после осмотра».

### 1.1 Квиз-подбор → ассистент (фирменная фишка каркаса)

- **Суть**: 4–6 вопросов с вариантами (тип заявки, срочность, объект…)
  вместо пустой формы; в конце — сводка ответов + имя/телефон.
- **Связка с ассистентом**: собранные ответы становятся текстом первого
  сообщения виджета («Нужна оценка квартиры после залива, срочно, документы
  есть») — карточка падает в колонку «Новая» уже с контекстом. У
  конструкторов квиз идёт в CRM, квиз→LLM-ассистент — нет. Дёшево:
  предзаполнение виджета, тот же канал `web`, без новых таблиц.
- **Честность**: отправка — только по явному клику посетителя, автосенда нет.
- **Реализация**: JS-lite. Вопросы — `fieldset/legend` + radio; подсветка
  выбранного и переход шагов — через `:has(:checked)` (CSS); сбор и отправка
  — один скрипт; прогресс «шаг 2 из 5» — в `aria`.
- **Темы**: А — стеклянные карточки-шаги; Б — шаги «этажами»; В —
  «опросник-блокнот» с рамками.

### 1.2 Калькулятор прикидки цены

- **Суть**: 1–2 слайдера + опции-чекбоксы → честная вилка «≈ 3 000–4 500 ₽»;
  финал — CTA «Отправить расчёт в заявку» (параметры едут вместе с ней) или
  «Обсудить в чате».
- **Правило доверия**: только вилка + подпись «точную стоимость назовём
  после осмотра»; «точная» цена из калькулятора — путь к конфликту.
- **Реализация**: JS-lite (`input range` + пересчёт); формулы — статикой во
  фронтенде рядом с услугами (§6 каркаса; переезд в БД — рост-точка).
- **Темы**: А — стеклянная шкала; В — «ценник» с крупными цифрами.

### 1.3 Sticky CTA-бар (мобильный)

- **Суть**: на 390px — фиксированный низ «Позвонить · Заявка · Чат» с
  `safe-area-inset-bottom`; прячется, когда блок заявки на экране.
- **Реализация**: CSS-only + 5 строк IntersectionObserver на скрытие; футер
  получает нижний отступ, чтобы бар не перекрывал контент; прячется при
  открытом виджете-чате.

### 1.4 Bottom sheet (мобильная модалка)

- **Суть**: модалка услуги на мобиле выезжает листом снизу, а не всплывает
  в центре — привычный жест из мобильных приложений.
- **Реализация**: `<dialog>` (§5) + transform-анимация на ≤640px; закрытие —
  подложка / Esc / кнопка; свайп-закрытие — рост-точка, не обязательно.
- **Референс**: модалка §3.3 каркаса — на десктопе остаётся 720px / 80vh.

## 2. Доверие

Набор выбирается под отрасль, 2–3 блока на витрину (пункт 5 §3 каркаса).

### 2.1 Слайдер «до/после»

- **Суть**: одна ручка поверх двух фото одной сцены. Автосервис (кузов,
  детали), сантехник (объекты); оценщику — условнее.
- **Реализация**: JS-lite (pointer events + сдвиг `clip-path`); подписи
  «до»/«после» — не только цветом; `aria-label`, управление стрелками.
- **Темы**: А — стеклянная ручка; В — рамка-ценник.

### 2.2 Стена отзывов

- **Суть**: лёгкая masonry-раскладка без JS (`columns`); каждый отзыв —
  текст + рейтинг + якорь-ссылка на источник (Яндекс/2ГИС).
- **Правило**: только реальные отзывы; для демо — пометка «макет».

### 2.3 Полка документов + lightbox

- **Суть**: сетка превью (дипломы, лицензии, сертификаты); клик — крупная
  версия в `<dialog>` (фокус-ловушка и Esc из коробки, §5).

### 2.4 Таймлайн «как мы работаем»

- **Суть**: `ol` из 3–4 шагов с номерами и линией; снимает страх «что будет
  после заявки».
- **Реализация**: CSS-only; появление шагов по скроллу — enhancement (§5),
  без него шаги просто видны.

### 2.5 Живая пилюля режима (авторский элемент)

- **Суть**: у точек контактов — «Сейчас открыто · до 19:00» / «Откроемся
  завтра в 9:00»; за час до закрытия — warning-оттенок.
- **Реализация**: график точки — JS-конфиг; обновление рекурсивным
  `setTimeout` раз в минуту; часовой пояс — клиентский (город заказчика).
- **Честность**: график не задан — пилюли нет, ничего не выдумываем.

### 2.6 Count-up цифр доверия

- **Суть**: цифры hero/блока доверия доезжают до значения при входе в экран.
- **Реализация**: JS-lite; значение лежит в DOM сразу (без JS числа видны),
  IntersectionObserver запускает анимацию; `prefers-reduced-motion` — без
  анимации.

### 2.7 Marquee-полоса доверия

- **Суть**: бегущая строка фактов («✔ Официально ✔ Без предоплаты ✔
  Сегодня…»).
- **Родословная**: придумана в теме В ([ui-designs.md](ui-designs.md), §2.3) —
  поднимаем в общий паттерн для всех тем: дубликат контента `aria-hidden`,
  пауза на hover/focus, reduced-motion → статичная строка.

## 3. Витрина (дозакрытие)

Карусель и гармошка описаны в §3.3 каркаса и здесь не дублируются.

### 3.1 Segmented control категорий

- **Суть**: когда услуг >10 — пилюли-переключатели «Ремонт / ТО / Кузов»
  над сеткой, фильтруют карточки; вместо бесконечной гармошки.
- **Реализация**: CSS-only — radio + `:has()`; JS-lite опционально для
  хеша в URL. A11y: нативные radio, клавиатура из коробки.

### 3.2 Spotlight-карточки

- **Суть**: радиальное свечение, следующее за курсором.
- **Реализация**: JS-lite; один делегированный `pointermove` пишет
  `--mx/--my`, карточка рисует `radial-gradient` в `::before`.
- **Темы**: А — блик на «стекле»; Б — «свет из глубины»; В — не нужен
  (жёсткая материя). Только fine pointer, выкл. при reduced-motion,
  декор — `aria-hidden`.

## 4. Кабинет

Только в приборной теме (§4 каркаса); витринной «милоты» здесь нет.

### 4.1 WIP-шкала колонки

- **Суть**: лимит незавершённых карточек на этап (KV-настройки воронки);
  шкала-«колодец» с заполнением; перегруз (>лимита) — warning, но не
  блокировка: сигнал менеджеру, решение за ним.
- **Стартовое правило**: лимит ≈ 1–1.5 × людей, работающих на этапе.

### 4.2 Sparklines у KPI

- **Суть**: мини-график заявок за 14 дней рядом с числом (шапка колонки,
  дашборд).
- **Реализация**: данные — агрегат `stage_log` тонким роутом
  `/api/<id>/stats` (П9); рендер — SVG polyline, JS-lite. Рост-точка: клик →
  разворот по этапам.

### 4.3 Drag&drop карточек

- **Суть**: перенос карточки между колонками мышью на десктопе.
- **Реализация**: HTML5 drag events; перенос статуса — через ту же дверь,
  что и кнопки (`Funnel`, один глагол — П12), второго пути к данным нет.
- **Обязательный фолбэк**: кнопки «←/→» на карточке (мобайл, клавиатура);
  карточка-призрак — `opacity: .5`.

### 4.4 Toast честных состояний

- **Суть**: «Черновик не отправился — нет сети» + кнопка «Повторить».
- **Реализация**: `role="status"`/`"alert"`; авто-скрытие рекурсивным
  `setTimeout`; никаких весёлых «успехов» поверх ошибки.

### 4.5 Empty states

- **Суть**: колонка без карточек — «Пока пусто — новые заявки появятся
  здесь» + подсказка действия; не красная «ошибка».
- **Реализация**: CSS-only; один компонент на все списки кабинета.

## 5. Инженерный слой: платформа вместо библиотек

Для vanilla-регламента (§2 каркаса) половина каталога удешевляется
платформенными API:

| Возможность | Поддержка | Даёт | Осторожно |
|---|---|---|---|
| `<dialog>` | Baseline 2022 | модалка/lightbox: фокус-ловушка, Esc, `::backdrop` | подложку стилизуем явно |
| `popover` | Baseline 2024 | тултипы/меню с light-dismiss без JS | top-layer — вне потока; позиционирование — anchor positioning (Chrome 125+) |
| `:has()` | Baseline 2023 | родительские состояния: сегмент-контрол, квиз, фильтры | длинные селекторы держим читаемыми |
| `details/summary` | везде | гармошка без JS | плавная высота — `interpolate-size` (Chrome) или grid-трюк; фолбэк — мгновенное раскрытие |
| CSS scroll-driven animations | Chrome/Edge 115+, свежий Safari; Firefox за флагом | прогресс чтения, появление секций, scrollytelling-таймлайн | только enhancement: без него — статика, и это норма |
| scroll-snap | везде | ленты с докруткой без карусельного JS | колесо мыши глобально не перехватываем |

Правило слоя: деградировавшее состояние всегда полноценное — «без анимации»
не баг, «без JS» не ломает контент.

## 6. Отброшенные паттерны (чтобы не возвращаться)

- **Fake social proof** («только что Иван оставил заявку», «онлайн 137») —
  против честности каркаса; в демо только с явной пометкой «макет».
- **Command palette (Ctrl+K)** — аудитория кабинета — владелец аптеки, не
  разработчик; рост-точка, не база.
- **Infinite scroll, мегаменю, хлебные крошки** — одностраничной витрине
  не нужны.
- **Библиотеки (Swiper, GSAP…)** — против регламента vanilla; по той же
  причине, что и WebGL-герои ([ui-designs.md](ui-designs.md), §3).

## 7. Порядок внедрения

1. **Квиз→ассистент→воронка** (§1.1) — фирменная фишка, единственная
   «связка» каталога.
2. **Набор доверия** (§2): до/после + пилюля режима + таймлайн.
3. **Кабинет** (§4): WIP-шкала + sparklines.
4. **Пере-одевание модалок на `<dialog>`/`popover`** — попутно, при
   касании кода.

Песочница: эксперимент `ui-patterns/` по [experiments.md](experiments.md)
(плитка в `registry.json`, первый шаг — статика): страницы-витрина
паттернов с переключателем темы А/Б/В поверх общих токенов.
