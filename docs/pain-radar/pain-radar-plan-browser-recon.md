# Радар болей — план исполнения 1.2: разведка 2ГИС и агент над браузером

Исполнение пункта 1.2 [глобального плана](pain-radar-global.md): разведка источника (Б11 разбора — фаза 2 начинается с разведки), расследование готовых MCP над headless-движками и выбор «агент или скрипт». Разведка выполнена **05.10.2026 живым браузером** (ZCode in-app browser, Chromium): главная 2ГИС, страница рубрик, листинг «Шиномонтаж», карточка организации; сетевые запросы сняты из реального трафика страницы, API-гипотезы проверены fetch'ем из контекста страницы и голым `curl` снаружи.

Главный результат: **сценарий кликов из плана не нужен** — вёрстка 2ГИС изменилась (атрибута `title` у ссылок рубрик больше нет), но вместе с ней отпала и необходимость парсить блоки: у рубрик стабильные URL с ID, а отзывы отдаются публичным JSON-API, которое отвечает даже голому curl без заголовков. Развилка «HTTP или браузер» для отзывов 2ГИС закрыта в пользу HTTP.

## 1. Разведка 2ГИС: что нашлось

### 1.1. Город — сегмент URL, гео по IP

Открытие `2gis.ru` без пути редиректит в город по IP (`2gis.ru/kursk`). Все внутренние ссылки содержат город первым сегментом: `/kursk/search/…`, `/kursk/firm/…`. Город/регион как параметр запроса — **подставляемый сегмент пути**, отдельного UI-клика не требует (открытый вопрос пункта 1.2 закрыт).

### 1.2. Каталог рубрик со стабильными ID (вместо парсинга блоков)

Страница `/kursk/rubrics` — полный список корневых рубрик, у каждой стабильный числовой ID в URL `/kursk/rubrics/subrubrics/<id>`:

| Рубрика | ID | Рубрика | ID |
|---|---|---|---|
| Поесть | 110539 | Услуги | 110565 |
| Автосервис | 110541 | Туризм | 110574 |
| Красота | 110543 | Спецмагазины | 110576 |
| Развлечения | 110545 | Продукты | 110582 |
| Медицина | 110549 | Спорт | 110585 |
| Автотовары | 110552 | Образование | 110588 |
| Товары | 110556 | Власть | 110593 |

Подрубрики открываются страницей `/rubrics/subrubrics/<id_группы>` и ведут сразу на листинги: «Автосервис» → Авторемонт `rubricId/9041`, Автомойки `405`, Шиномонтаж `7689`, Авторазбор `406`, Заправки `18547` (и «Ещё» → группа `111548` для раскрытия остальных). Значит **справочник «сфера → рубрики» — это константа проекта** (ID исторически стабильны), а не результат кликов: браузерная разведка нужна только для редкой сверки справочника.

### 1.3. Листинг организаций — SSR, данные в HTML

Страница `/kursk/search/Шиномонтаж/rubricId/7689` отдаёт список **серверным рендером**: карточки организаций есть в DOM сразу после загрузки (без XHR), полный массив лежит в `window.initialState` (~585 КБ на страницу). В карточке: название, ссылка `/kursk/firm/<branch_id>`, рейтинг, число оценок, адрес, рубрики. Заголовок «Места 195» — **счётчик организаций в рубрике**, готовый знаменатель для А1 (доля организаций-носителей боли). В base64-параметре `stat` ссылок — распаковываемый JSON с координатами и rubricId.

Прямой запрос к каталог-API (`catalog.api.2gis.ru/3.0/items?q=…&location=…`) с фронтовым ключом в трёх пробных наборах параметров вернул пустые `items` — точный контракт поиска каталога ещё подобрать (мелкая разведка, см. открытые вопросы); фронт использует `/3.0/markers/clustered` для карты. Пока рабочий путь листинга — HTML + `initialState`.

### 1.4. Отзывы — публичный JSON-API, работает без браузера (главная находка)

На карточке организации вкладка отзывов — прямой URL `/kursk/firm/<id>/tab/reviews`, число отзывов видно заранее. Сняты фактические запросы фронта; основной:

```
https://public-api.reviews.2gis.com/3.0/branches/<branch_id>/reviews
    ?limit=50&offset=0
    &rated=true                      ← без этого отзывы не отдаются
    &sort_by=date_edited             (или trust — дефолт фронта)
    &fields=meta.branch_rating,meta.branch_reviews_count,meta.total_count,…
    &key=<фронтовый ключ>&locale=ru_RU
```

- Отвечает **голому curl без единого заголовка** (проверено снаружи, без браузера): HTTP 200, JSON.
- Мета: `branch_rating`, `branch_reviews_count`, `total_count`, `next_link` — пагинация по offset, «от новых к старым» при `sort_by=date_edited` — ровно контракт карточных источников `reviews(ref, since, signal)` каркаса.
- Отзыв: `id`, `rating` (1–5), `text`, `date_created`/`date_edited`, `provider` (2gis/flamp/otello/booking/tbank/avito…), `official_answer` (ответ организации — отдельный сигнал), `user` (имя — ПДн, не сохраняем), `trust_factors`, `media`.
- Рядом: `/3.0/objects/ratings/light?object_ids=<до N шт.>` — рейтинги пачкой (быстрый обход каталога), `/2.0/reviews/<id>/comments` — обсуждения, `/2.0/objects/branch/<id>/facts` — факты, `/2.0/objects/<id>/summary` — сводка.
- Ключ — публичный фронтовый (`6e7e1929-…-d601860389bd`), лежит в открытом бандле 2gis.ru; при смене — перепоймать из трафика одной загрузкой страницы.

## 2. Вывод по развилке «HTTP или браузер» (Б11)

| Задача | Путь | Браузер нужен? |
|---|---|---|
| Отзывы организации | HTTP: `public-api.reviews.2gis.com` | **нет** |
| Список организаций рубрики | SSR HTML + `initialState` | нет (fallback — Playwright) |
| Счётчик рубрики («Места N») | SSR HTML | нет |
| Справочник рубрик | константа проекта + редкая браузерная сверка `/rubrics` | редко |
| Яндекс Карты (фаза 6) | не разведано; ожидается JS-токены + SmartCaptcha | да (patchright, Д2) |
| Ремонт источников / новая разведка | браузер + агент | да |

Итог: производственный сбор 2ГИС — **скрипт на каркасе сборщиков** (`fetchText`/`fetchJson`, троттлинг per-resource, сырьё в `collector_items` — В1); браузер — запасной двигатель и инструмент разведки. Сценарий «клик по `<a title="Рубрики">` → родитель на 3–4 уровня» устарел вместе с вёрсткой — вместо стратегии ремонта селекторов: справочник ID + два независимых канала (SSR-листинг, отзывное API), каждый чинится отдельно.

Осторожность: API неофициальный (ключ публичный, но ToS не разрешает сбор); держим вежливый темп (`throttle_ms` реестра ресурсов), кэш сырья (В1 — повторный разбор без обращений к источнику), «источник сломался» (Б5) при аномалиях; юридическая оценка перед публичным запуском (А7, открытый вопрос 5 глобального плана) — в силе.

## 3. Расследование MCP: агент над готовым MCP против своего API

| Кандидат | Что | Лицензия | Активность (05.10.2026) | Стек |
|---|---|---|---|---|
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) (`@playwright/mcp`) | официальный сервер Microsoft: 70+ инструментов (`browser_snapshot`, `browser_navigate`, `browser_click`…), работа по **accessibility-дереву**, без скриншотов | Apache-2.0 | v0.0.83 (28.09.2026), 37.8k звёзд, активно | Node, под капотом Playwright 1.64 |
| [browser-use](https://github.com/browser-use/browser-use) | агентная библиотека/сервер над Playwright, LLM-нативная | MIT | 117k звёзд, активно | **Python** |
| puppeteer-based MCP-серверы |community-форки, меньше коммьюнити | разные | разнобой | Node |
| Свой API над движком | «найди рубрику», «дай 5 организаций» — функции над Playwright | наш | — | Node |

Выводы:

1. **Для производственного сбора агент не нужен вовсе** — после разведки цепочка «сфера → рубрики → организации → отзывы» детерминирована (справочник ID + SSR + API). Зашивать её в LLM-агента — усложнение без выгоды (тот же аргумент, что Б11: скрипт там, где известен маршрут).
2. **Агент нужен для разведки и ремонта**: проверить источник после смены вёрстки, найти новый endpoint, прогнать «здравствуй, Яндекс» перед подключением. Здесь **Playwright MCP — готовый слой**: тот же стек (Node), та же база (Playwright по решению 1.1/Д1), Apache-2.0, живая разработка Microsoft, accessibility-дерево вместо хрупких селекторов. Свой API над движком писать не стоит: MCP уже даёт «найди/кликни/снапшот», а наши доменные операции («найди рубрику X») — тонкий промпт поверх.
3. browser-use — силён, но Python: второй стек на VDS ради инструмента разведки не оправдан; вернуться, если Playwright MCP упрётся.

## 5. Открытые вопросы (передать дальше)

1. **Контракт поиска каталога** (`catalog.api.2gis.ru/3.0/items`): точный набор параметров выдачи организаций запросом без HTML — три пробы вернули пусто; либо подобрать параметры, либо остаться на SSR-канале (Р3).
2. **Смена фронтового ключа**: как часто 2ГИС ротирует `key`; проверка живости ключа при старте джобы (Р5).
3. **Яндекс Карты** — разведка перед фазой 6: JS-токены, SmartCaptcha, реально ли там HTTP-канал (ожидание: нет, браузер с patchright по Д2).
4. **ToS/юридика** (открытый вопрос 5 глобального плана): неофициальное использование публичного API — позиция А7 «показать юристу» перед публичным запуском.
