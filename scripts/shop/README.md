# Сайт магазина

Витрина для покупателей (каталог с поиском, «заявка списком», окно статуса заявки,
ассистент в чате, политика обработки ПДн) и кабинет сотрудников (доска заявок,
черновики счетов с выгрузкой в 1С, замеры, каталог из xlsx, разговоры ассистента,
магазины и сотрудники). Версия сборки — `build.json` (коммит и дата).

## Что нужно

- Node.js 20+ (лучше 22), Postgres 14+; docker не нужен.
- Сервер от 1 vCPU и 1 ГБ памяти (на 1 ГБ — swap 1–2 ГБ), диск от 15 ГБ.

## Запуск

```bash
createdb shop                        # база; владелец — пользователь из DATABASE_URL
cp .env.example .env                 # заполнить: база, SESSION_SECRET, ADMIN_EMAILS, почта, модель
npm ci --omit=dev
npm start                            # «Shop running at …»; миграции накатываются при старте
```

## Адреса

| Адрес | Что |
|---|---|
| `/` | витрина магазина `SHOP_HOME` |
| `/backbone/?shop=<адрес>` | витрина любого магазина экземпляра |
| `/backbone/privacy.html?shop=<адрес>` | политика обработки ПДн магазина |
| `/cabinet/` | кабинет: вход сотрудников и админа |

## Первая настройка

1. `/cabinet/` → «Войти» → почта из `ADMIN_EMAILS` и пароль из `ADMIN_PASSWORD` (учётку
   админа сайт заводит при старте). Сразу «Пароль» вверху → свой пароль, затем стереть
   `ADMIN_PASSWORD` из `.env`. Регистрации на сайте нет — учётки выдаёт админ.
2. «Настройки и доступ» → «Завести магазин»: адрес латиницей (например `metiz-kursk`), название,
   ниша, дни и часы работы, почта магазина (на неё — письма о заявках и ответы покупателей).
   Адрес — в `SHOP_HOME` в `.env`, перезапуск: корень сайта ведёт на этот магазин.
3. Выбрать магазин вверху → «Каталог» → «Загрузить файл выгрузки» (xlsx из 1С, МойСклад
   или прайс) → проверить колонки → «Загрузить каталог».
4. «Настройки и доступ» → отметить магазин → «Добавить сотрудника» → почта сотрудника: сайт заведёт
   учётку и покажет пароль один раз. Передайте почту и пароль сотруднику лично: он войдёт
   на `/cabinet/`, увидит только свой магазин и сменит пароль кнопкой «Пароль». Если у
   почты уже есть учётка — вместо пароля одноразовая ссылка-приглашение на 7 дней.
5. Тестовая заявка с витрины на свой ящик: квитанция покупателю и «Новая заявка №…» на
   почту магазина; в кабинете в таблице писем — «отправлена».

Первые 14 дней разбор заявок нового магазина — «Сравнение»: черновик счёта скрыт, менеджер
работает как раньше и в карточке заявки жмёт «Мой счёт готов» со своим счётом из 1С — потом
«глаз» показывает черновик рядом. Тумблер «Выключен / Сравнение / Помощь» — наверху экрана
«Черновики счетов»; «До и после» простыми словами — на экране «Замеры». При нескольких
магазинах вкладка «Настройки и доступ» зовётся «Магазины».

## Почта

По умолчанию письма всех магазинов сервера уходят с общего ящика — домена для рассылки
(`BACKBONE_MAIL_FROM` и `BACKBONE_SMTP_*` в `.env`): «Название магазина» <noreply@домен
рассылки>, ответ покупателя — на почту магазина. Домен рассылки — отдельный от основного, на
Яндекс 360, с записями MX, SPF (`v=spf1 redirect=_spf.yandex.net`), DKIM (`mail._domainkey`,
ключ из Яндекс 360) и DMARC (`_dmarc`: сначала `p=none`, потом `p=quarantine`); отправитель —
пароль приложения ящика `noreply@`. Проверка: тестовая заявка → в письме SPF, DKIM, DMARC — `pass`.

Свой ящик магазина — по желанию заказчика, включает только админ: в `.env` —
`BACKBONE_MAIL_KEY` (`openssl rand -hex 32`, копия — вне сервера), затем «Настройки и
доступ» → «Почта магазинов» → отметить магазин → «Свой ящик магазина» (сервер, порт, логин,
пароль приложения, отправитель) → «Проверить отправку»: тестовое письмо уходит на почту
магазина, и только после него письма магазина идут с его ящика. Пароль в базе — шифром.

В письмах покупателю — только текст сайта (фразы по шагу заявки, номер, срок, ссылка) и
название магазина; на один адрес — не больше 10 писем в сутки. У заявки хранятся IP и время
отправки («Данные покупателей») — для разбора жалоб; удаляются вместе с данными покупателя.

## Служба и nginx

`/etc/systemd/system/shop.service`:

```ini
[Unit]
Description=Сайт магазина
After=network.target postgresql.service

[Service]
User=shop
WorkingDirectory=/opt/shop/app
ExecStart=/usr/bin/node shop.js
Restart=always
RestartSec=5
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

nginx — прокси на `127.0.0.1:3000` (`HOST=127.0.0.1`, `TRUST_PROXY=true` в `.env`),
`client_max_body_size 12m` (прайс до 10 МБ), `proxy_read_timeout 300s` (модель отвечает
до 3 минут), HTTPS — `certbot --nginx -d <домен>`.

## Обновление

Новая версия приходит архивом сборки `shop.tar.gz`. Распаковать рядом, перенести `.env`,
поставить зависимости и подменить папку; прежняя остаётся для отката:

```bash
cd /opt/shop
sudo -u shop mkdir app.new
sudo -u shop tar -xzf /tmp/shop.tar.gz -C app.new --strip-components=1
sudo -u shop cp app/.env app.new/.env
(cd app.new && sudo -u shop npm ci --omit=dev)
sudo systemctl stop shop
sudo -u shop rm -rf app.old && sudo -u shop mv app app.old && sudo -u shop mv app.new app
sudo systemctl start shop            # новые миграции накатятся при старте
```

## Бэкап

Раз в сутки `pg_dump -Fc shop > shop-$(date +%F).dump`, копию — вне сервера.
Восстановление: `pg_restore -d shop --clean <файл>`.
